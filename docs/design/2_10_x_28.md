# 초고속 2차원 대용량 데이터(10만 행 × 28열) 시각화 및 벤치마크 플랫폼 구축 계획서

* **문서 버전:** v3.0 (OWID 글로벌 기후·에너지 실측 데이터셋 확정판)
* **기술 스택:** Rust (Axum + rmp-serde + rust_xlsxwriter) + SolidJS + Canvas/WebGL + Web Worker
* **데이터 소스:** Our World in Data (`owid/co2-data` & `owid/energy-data` 통합 스키마)
* **배포 인프라 (100% 무과금):** Koyeb Free Eco (백엔드) + Cloudflare Pages (프론트엔드)
* **핵심 목표:** 실제 글로벌 기후·에너지·경제 거시 통계 100,000 행 × 28개 컬럼($2,800,000$ 셀)을 단일 뷰포트(`100vw × 100vh`) 내에 4종 멀티 차트와 2차원 가상화 그리드로 60fps 렌더링하고, 블로킹 없이 CSV/TSV/Excel로 즉시 추출하는 고성능 데이터 분석 플랫폼 구축

## 1. 시스템 아키텍처 및 데이터 부트스트래핑 설계

Koyeb 무료 티어(512MB RAM, 0.1 vCPU)의 메모리 한계를 준수하면서 실제 공공 데이터의 통계적 유의미성과 10만~30만 건의 벤치마크 볼륨을 동시에 확보하는 구조입니다.

```
[GitHub Raw Data Source / Embedded Zstd Asset]
 ├── owid/co2-data (https://raw.githubusercontent.com/owid/co2-data/master/owid-co2-data.csv)
 └── owid/energy-data (https://raw.githubusercontent.com/owid/energy-data/master/owid-energy-data.csv)

       ▼ (컨테이너 빌드 시 Zstd 압축 내장 약 1.8MB -> 서버 기동 시 1회 인메모리 적재)

[Rust Backend (Koyeb Free Eco: 512MB RAM 제한)]
 ├── 부팅 시 원본 데이터(약 5만 행) 파싱 및 월별/분기별 선형 보간(Linear Interpolation) 증폭
 ├── 10만~30만 행 × 28열 정적 구조체 배열(`LazyLock<Vec<ClimateRecord>>`) 유지 (RAM 약 45MB 고정)
 ├── Zero-Copy 슬라이싱 참조 (&[ClimateRecord])
 ├── 직렬화 엔진: MessagePack (rmp-serde) vs JSON (serde_json) + Zstd/Brotli 압축
 └── 서버 사이드 엑셀 엔진: rust_xlsxwriter 기반 초고속 .xlsx 바이너리 스트림 생성

       ▼ (HTTP/2 Binary Stream / 3.5~5.5MB Compressed Payload)

[Frontend Web Worker (Background Thread)]
 ├── 네트워크 패치 및 압축 해제 / MessagePack 역직렬화
 ├── 차트용 사전 집계 (LTTB 시계열 다운샘플링, 탄소 집약도 히스토그램 Binning, 대륙별 GroupBy)
 ├── 10만 행 × 28열 다중 조건 교차 필터링(Cross-filter) & 고속 인덱스 정렬
 └── 클라이언트 사이드 CSV / TSV Blob 청크 빌더 (UTF-8 BOM)

       ▼ (Transferable Objects / 뷰포트 인덱스 및 차트 버퍼 전달)

[SolidJS Main Thread (Single Screen UI: 100vw × 100vh)]
 ├── Zone A (상단 8%): 볼륨/포맷 컨트롤 & 실시간 텔레메트리 스코어보드 & 파일 추출 바
 ├── Zone B (중단 32%): 4종 기후·에너지 인터랙티브 Canvas/WebGL 멀티 차트 클러스터
 └── Zone C (하단 60%): 2차원(행+열) 가상화 그리드 & 좌우 고정 핀(Pinned) 컬럼 & 요약 푸터
```

### 3.1. 4대 기후·에너지 차트 클러스터 (Zone B) 상세 설계

1. **Chart 1 — 글로벌 탄소 배출량 및 기온 상승 기여도 시계열 추이 (Canvas Line/Area):**
   * 10만~30만 건의 시계열 데이터를 Web Worker에서 **LTTB(Largest-Triangle-Three-Buckets)** 알고리즘으로 800개 포인트로 압축하여 5ms 내에 그립니다.
   * 차트 위에서 마우스로 특정 연도 구간(예: `1990 ~ 2024`)을 드래그(Brush)하면 하단 표와 나머지 3개 차트가 즉시 해당 기간으로 동기화됩니다.
2. **Chart 2 — 전력 탄소 집약도(`carbon_intensity`) 및 재생에너지 비중 분포 (Histogram):**
   * 전체 레코드의 탄소 집약도($0 \sim 1000\text{ gCO}_2/\text{kWh}$)를 `Float32Array` 버킷 연산으로 25개 구간(Bin) 집계하여 분포도를 실시간으로 표현합니다.
3. **Chart 3 — 대륙 및 소득 그룹별 에너지 믹스 (Stacked Bar Chart):**
   * `Asia`, `Europe`, `North America` 등 대륙별로 화석연료(`fossil_share`), 원자력(`nuclear_share`), 재생에너지(`renewables_share`) 평균 비중을 누적 막대로 시각화합니다.
   * 특정 대륙 막대를 클릭하면 하단 10만 건 그리드가 해당 대륙 소속 국가들로 10ms 내에 교차 필터링(Cross-filtering)됩니다.
4. **Chart 4 — 1인당 GDP(X축) vs 1인당 $\text{CO}_2$ 배출량(Y축) 상관관계 산점도 (Canvas Pixel Buffer / WebGL):**
   * 10만 개의 데이터 포인트를 X축(소득), Y축(탄소 배출), 색상(대륙 구분)으로 매핑하여 `ImageData` 버퍼에 직접 찍어냄으로써 경제 성장과 탄소 배출의 상관관계를 한눈에 보여줍니다.

### 3.2. 2차원(행+열) 가상화 및 빠른 탐색 UX (Zone C)

* **2D Virtualization (`rowVirtualizer` + `columnVirtualizer`):**
  * 좌측 고정 4개 컬럼(`record_id`, `iso_code`, `country`, `period_str`)과 우측 고정 1개 컬럼(`temp_change_ghg`)은 항상 화면 양끝에 고정(Sticky)됩니다.
  * 중앙의 23개 가변 컬럼은 가로 스크롤 위치에 따라 현재 뷰포트에 노출되는 6~8개 컬럼만 DOM에 마운트합니다.
  * 세로 10만 행 중 현재 보이는 22개 행만 유지하므로, 총 $2,800,000$개의 셀 중 **실제 DOM에 존재하는 셀은 항상 약 $22 \times 12 = 264$개**로 제한되어 가로·세로 대각선 고속 스크롤 시에도 60fps를 유지합니다.
* **컬럼 그룹 탭 점프:** 28개 컬럼을 일일이 가로 스크롤하지 않도록 그리드 상단에 `[거시경제(Col 5~9)]`, `[온실가스(Col 10~16)]`, `[배출원(Col 17~20)]`, `[에너지믹스(Col 21~27)]` 원클릭 가로 스크롤 점프 버튼을 제공합니다.

## 4. 대용량 파일 추출(Export) 아키텍처 (CSV / TSV / Excel)

10만 행 × 28열($2,800,000$ 셀)을 추출할 때 브라우저 멈춤이나 메모리 초과(OOM)가 발생하지 않도록 작업 주체를 분리합니다.

| 추출 포맷 | 처리 주체 | 구현 메커니즘 | 예상 파일 크기 (10만 행) | 목표 소요 시간 |
| :--- | :--- | :--- | :--- | :--- |
| **CSV (`.csv`)** | **Frontend Web Worker** | 워커 메모리에 있는 배열을 10,000행 단위 문자열 청크로 변환 후 `new Blob(chunks, { type: 'text/csv;charset=utf-8' })` 조립 (한글·특수기호 깨짐 방지용 UTF-8 BOM `\uFEFF` 삽입) | 약 18 ~ 22 MB | **180ms ~ 350ms** (UI 블로킹 0ms) |
| **TSV (`.tsv`)** | **Frontend Web Worker** | 탭(`\t`) 구분자 기반으로 고속 문자열 결합 후 `Blob` URL 생성 (엑셀에 바로 붙여넣기 최적화된 포맷) | 약 18 ~ 22 MB | **150ms ~ 300ms** (UI 블로킹 0ms) |
| **Excel (`.xlsx`)** | **Rust Backend Stream** | `/api/export/xlsx` 호출 시 Rust 서버가 `rust_xlsxwriter` 크레이트를 사용해 인메모리에서 네이티브 속도로 `.xlsx` ZIP/XML 바이너리를 생성하여 스트리밍 다운로드 응답 | 약 7 ~ 10 MB | **450ms ~ 900ms** |

* **추출 범위 선택 옵션:** `[전체 원본 추출(10만~30만 건)]` 또는 `[현재 차트/검색으로 필터링 및 정렬된 결과만 추출]`을 선택할 수 있도록 구성하며, 추출 완료 시 상단 텔레메트리 바에 **"추출 소요 시간: 210ms | 파일 크기: 19.4MB"**를 기록합니다.

## 5. 단계별 상세 작업 계획 (Work Breakdown Structure)

### Phase 1: OWID 데이터 전처리 및 Rust 인메모리 부스터 엔진 구축
1. **데이터 에셋 준비 스크립트 작성:** `owid-co2-data.csv`와 `owid-energy-data.csv`를 `iso_code` + `year` 키로 병합(Join)하여 28개 핵심 컬럼만 정제한 뒤 Zstd로 고압축(`owid_merged.bin.zst`, 약 1.8MB)하여 `/backend/assets/`에 내장합니다.
2. **인메모리 시계열 보간 증폭기(Interpolator) 구현:** 서버 기동 시 압축 파일을 읽어 5만 건의 원본 배열을 생성하고, 연속된 연도 사이에 반기(2배, 10만 건) 또는 월간(6배, 30만 건) 선형 보간 값을 생성하여 정적 메모리(`LazyLock`)에 적재합니다.
3. **Koyeb 512MB RAM 방어 검증:** 30만 건 적재 상태에서도 서버 전체 RSS 메모리 점유율이 80MB를 넘지 않도록 `String` 대신 고정 길이 배열 또는 인터닝(String Interning: 국가명, 대륙명 등 반복 문자열 공유)을 적용합니다.

### Phase 2: 고성능 다중 직렬화 API 및 서버 사이드 Excel 추출기 구현
1. **벤치마크 데이터 API (`/api/records`):** 쿼리 파라미터(`rows=50000|100000|300000`, `format=msgpack|json`)에 따라 인메모리 슬라이스를 직렬화하고, 소요 시간을 `X-Server-Serialize-Ms` 헤더에 담아 반환합니다.
2. **서버 사이드 Excel 추출 API (`/api/export/xlsx`):** 필터 조건(대륙, 연도 범위, 검색어)을 쿼리로 받아 `rust_xlsxwriter`로 헤더 스타일링 및 숫자 포맷이 적용된 `.xlsx` 파일을 메모리 버퍼로 생성해 내려줍니다.
3. **압축 및 CORS 레이어 구성:** `tower-http`의 `CompressionLayer`(Zstd/Brotli/Gzip)와 `CorsLayer`(`Access-Control-Expose-Headers: X-Server-Serialize-Ms`)를 설정합니다.

### Phase 3: 프론트엔드 Web Worker 데이터 엔진 및 사전 집계 파이프라인 구축
1. **비동기 디코딩 워커 구현:** `fetch` 수신부터 `@msgpack/msgpack` 디코딩까지 워커 내부에서 처리하여 메인 스레드 Long Task를 완전히 제거합니다.
2. **고속 차트 집계기 구현:** 데이터 디코딩 직후 워커 안에서 4개 차트용 데이터(LTTB 시계열 배열, 25개 구간 히스토그램 카운트, 대륙별 에너지 믹스 평균, 산점도 좌표 `Float32Array`)를 1회 순회($O(N)$)로 동시에 계산하여 메인 스레드로 전송합니다.
3. **워커 내장 CSV/TSV 추출기 구현:** 현재 활성화된 인덱스 배열을 기반으로 청크 단위 `Blob`을 생성하고 `ObjectURL`을 반환하는 비동기 메시지 핸들러를 작성합니다.

### Phase 4: 단일 뷰포트 멀티 차트(Zone B) 및 2D 가상화 그리드(Zone C) 구현
1. **3단 고정 레이아웃 스캐폴딩:** `100vw × 100vh` CSS Grid 레이아웃으로 상단 바(8%), 차트 존(32%), 그리드 존(60%)을 고정 배치합니다.
2. **Canvas 기반 4종 차트 바인딩:** uPlot 및 HTML5 Canvas 2D Context를 활용해 4개의 차트를 렌더링하고, 드래그(Brush) 및 클릭 이벤트를 워커 필터링 명령과 연결합니다.
3. **2차원 가상화 테이블(`@tanstack/solid-virtual`) 구현:** 세로 `rowVirtualizer`와 가로 `columnVirtualizer`를 교차 바인딩하고, 좌측 4열·우측 1열 Sticky 고정 및 셀 내부 인라인 데이터 바/게이지 컴포넌트를 최적화합니다.
4. **하단 고정 요약 행(Sticky Summary Row) 연동:** 필터링 조건이 바뀔 때마다 총 건수, 누적 탄소 배출량 합계, 평균 재생에너지 비중, 평균 탄소 집약도를 즉시 갱신합니다.

### Phase 5: 무과금 배포 파이프라인 연결 (Koyeb + Cloudflare Pages)
1. **Rust 멀티스테이지 Dockerfile 작성:** `rust:alpine` 빌더에서 정적 바이너리와 `owid_merged.bin.zst` 에셋만 경량 런타임 이미지로 복사하여 20MB 이하의 컨테이너 이미지를 구성합니다.
2. **Koyeb 백엔드 배포:** Koyeb Free Eco(`eNano`, 512MB RAM, Tokyo 리전, 포트 8000)에 배포하고 `/health` 엔드포인트를 연결합니다.
3. **Cloudflare Pages 프론트엔드 배포:** SolidJS 빌드 산출물(`dist`)을 Cloudflare Pages에 연결하고 프로덕션 API 환경 변수를 주입합니다.

## 6. 품질 및 성능 검증 체크리스트 (Evaluation Checkpoints)

1. **[백엔드 메모리]** 30만 행 × 28열 데이터를 메모리에 적재한 상태에서 Koyeb 컨테이너 RAM 사용량이 100MB 미만으로 유지되는가?
2. **[직렬화 속도]** 10만 행 × 28열 기준 MessagePack 직렬화 및 압축 응답 시간이 JSON 대비 2배 이상 빠르며 페이로드가 5MB 이하인가?
3. **[무블로킹 파싱]** 10만 행 수신 및 차트 사전 집계 동안 브라우저 메인 스레드의 FPS가 55fps 이상으로 유지되는가?
4. **[2D 가상화 DOM 제어]** 10만 행 × 28열($2,800,000$ 셀) 로드 후 실제 DOM 트리 내 셀(`.grid-cell`) 엘리먼트 개수가 항상 350개 미만인가?
5. **[차트-그리드 동기화]** 상단 차트에서 특정 연도 구간 드래그 또는 대륙 클릭 시 10만 건 그리드와 요약 푸터가 50ms 이내에 갱신되는가?
6. **[고속 파일 추출]** 10만 행 × 28열 전체 데이터를 CSV/TSV로 추출할 때 화면 멈춤 없이 500ms 이내에 다운로드가 시작되며, Excel(`.xlsx`) 추출 시 한글 및 숫자가 깨지지 않는가?
